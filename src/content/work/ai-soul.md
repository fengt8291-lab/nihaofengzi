## 项目背景

AI Soul 最初是一个带有通行码、渠道运营和付费流程设想的测试产品。随着项目定位转向个人网站作品展示，我将它收敛为一个更轻、更清楚的 AI 体验：用户完成20道题，系统计算六维特征、匹配一个 AI 人格，再生成一段定制化解读。

它不是心理测评，也不试图给用户下结论。项目更关心的是，规则计算、AI 生成和情绪化表达如何组合成一次完整而克制的互动体验。

## 核心判断

- 评分与匹配必须由本地确定性逻辑完成，不能把所有判断交给大模型；
- AI 只接收六维结果和匹配画像，不接收用户逐题答案；
- 生成失败不能中断用户流程，每个 AI 人格都需要独立的本地兜底内容；
- 娱乐性测试必须明确边界，避免包装成心理诊断或医疗建议；
- 个人作品 Demo 不需要支付、用户系统和复杂运营模块。

## 我的具体贡献

我重新确认了项目定位和用户流程，审计并清理历史工程，统一体验码为 `findsoul`，保留20题、六维评分和 AI 人格匹配，使用 DeepSeek API 生成结果页中的定制化解读。

在工程侧，我将 API Key、后台密码和 Flask 密钥移入环境变量，重建匿名测试记录与统计后台，补充输入校验、安全响应头、依赖漏洞检查和自动化测试，并完成 GitHub 整理、Gunicorn、systemd、Nginx 与 HTTPS 部署。

## 当前体验

用户输入统一体验码后完成20道题，获得六维评分、AI 人格匹配结果和一段由 DeepSeek 生成的心灵解读。后台只保存匿名测试时间、答案、评分、匹配结果和 AI 生成状态，用于观察产品运行情况。

## 已完成成果

- 建立匿名 SQLite 记录、统计后台和180天自动清理；

## 限制与下一步

题目、六维权重和 AI 人格画像仍属于娱乐性产品设计，不具备专业心理测量效度。后续会根据真实使用记录和用户反馈继续精简结果页、校准文案，并观察 AI 生成成功率和响应时间。
